# 五镜详解：五本书各自解决什么问题

> 读法：先看「一句话」和「诊断问题」，需要时再看概念词典与局限。
> 重要：五本书不是五个真理，而是五个**有条件**的镜头。每条结论都要问「在什么产品、什么场景、什么阶段成立」。

---

## 1. 俞军《产品方法论》：值不值得做，和谁交易

### 一句话

产品是交易的载体；产品经理的核心产出是**持续做出高质量的价值判断**，而不是文档。

### 核心模型

**（1）用户是需求的集合，不是自然人**

- 同一个人在不同场景、不同动机下，是不同「用户」。
- 用人口属性（25 岁、女性、一线城市）描述用户，几乎不能指导设计；用「需求 + 场景 + 约束」描述才有用。
- 推论：不要问「我们的用户是谁」，要问「我们在什么场景下满足谁的什么需求，还有哪些需求未被满足」。

**（2）用户价值公式**

```
用户价值 =（新体验 − 旧体验）− 替换成本
```

- **新体验**：产品带来的效用增量，最好能落到时间、成本、收益、风险、情绪中的某一项。
- **旧体验**：用户当前的替代方案，不只是竞品，还包括 Excel、微信群、人工、外包、以及「什么都不做」。
- **替换成本**：学习成本、迁移成本、习惯成本、关系/社交成本、风险成本、采购与合规成本。

这个公式最重要的用途不是算出一个数，而是**逼你把三项分别说清楚**。多数产品失败，不是新体验不够好，而是低估了旧体验的惯性和替换成本。

**（3）交易模型与交易成本**

- 产品价值往往来自「促成交易」或「降低交易成本」。
- 交易成本包括：搜寻、比较、决策、履约、信任、纠纷处理。
- 平台型产品尤其要画清：谁付钱、谁使用、谁供给、谁承担风险、谁可能受损。

**（4）效用与边际效用递减**

- 同一需求被反复满足，效用递减。产品要么持续创造新效用，要么降低门槛扩大人群，要么转向新的需求集合。
- 这解释了为什么「功能加得越多，用户越无感」：新增功能可能只覆盖了低频需求，边际效用极低。

**（5）决策质量**

- 真正的成本是**机会成本**：做 A 的代价是没做 B。
- 决策质量 ≠ 结果质量。好决策可能坏结果，坏决策可能好结果；复盘要区分两者。
- 可逆决策快做，不可逆决策慢做。

### 概念词典

| 概念 | 含义 | 怎么用 |
|---|---|---|
| 需求的集合 | 用户是若干需求的集合，不是一个人格 | 拆场景与需求，而不是给人群贴标签 |
| 旧体验 | 用户当前的替代方案 | 访谈时必问「你现在怎么做这件事」 |
| 替换成本 | 用户切换要付出的代价 | 逐项列：学习/迁移/习惯/关系/风险/采购 |
| 交易成本 | 达成交易的全部摩擦 | 找出你降低了哪一类摩擦 |
| 效用 | 需求被满足的程度 | 用「省了多少时间/少了多少风险」表达 |
| 边际效用 | 每多一次消费带来的新增满足 | 判断功能优先级与复购动力 |
| 机会成本 | 放弃的最佳替代方案 | 排优先级时问「不做这个做什么」 |

### 诊断问题

1. 用户现在的替代方案到底是什么？包括「不做」吗？
2. 新体验的增量，能否用一句话或一个数字说清？
3. 替换成本有哪些？由谁承担？我们有没有帮用户降低它？
4. 这笔交易里，谁付钱、谁使用、谁受损？
5. 我们降低的是哪一类交易成本？
6. 这个需求属于哪个「需求集合」？同一人群还有哪些相邻场景？
7. 做这件事的机会成本是什么？
8. 这是可逆决策还是不可逆决策？

### 局限与误用

- **把公式当精算**：早期没有数据时，公式容易变成主观打分。正确用法是「结构化地说清假设」，不是「算出小数点」。
- **忽略旧体验的惯性**：用户不换，往往不是因为新方案不好，而是因为旧方案「够用且熟悉」。
- **过度经济理性**：对身份、审美、情绪、社交展示的解释力弱，需要用诺曼与原研哉补。
- **只看用户价值，不看交付成本**：可持续的前提是「创造的价值 − 交付成本」为正。

### 与其他镜头的接口

- 俞军定「值不值得」，诺曼定「能不能用」，原研哉定「有没有感觉」，埃亚尔定「会不会再来」，杨堃定「能不能在组织里跑起来」。

## 2. 诺曼《设计心理学》：用户能不能看懂、能不能做成

### 一句话

当用户犯错时，先修设计，不要修用户。

### 核心模型

**（1）可供性（affordance）与意符（signifier）**

- 可供性：物的属性与人的能力之间「可以做什么」的关系。
- 意符：告诉用户「这里可以做什么、怎么做」的可见线索。
- 数字产品没有物理可供性，**几乎全靠意符**：按钮的形状、文案、位置、光标、动效、空状态提示。

**（2）映射（mapping）**

- 控件与结果之间的空间/逻辑对应关系。自然映射降低学习成本。
- 例：音量滑块向上 = 变大；地图拖动方向 = 内容移动方向；表单分组与心理模型一致。

**（3）反馈（feedback）**

- 每个动作都要有即时、可理解、可行动的反馈。
- 反馈不是「弹个 toast」，而是让用户知道：发生了什么、系统处于什么状态、下一步能做什么。

**（4）概念模型（conceptual model）**

- 用户心里对系统「是什么、怎么运作」的解释。
- 设计师模型 ≠ 用户模型，是绝大多数「不会用」的根因。
- 好的概念模型能用一张图讲清：有哪些对象、什么状态、什么动作、什么规则。

**（5）约束与惯例**

- 约束：让错误动作不可能或难以发生（禁用、限制输入、物理/逻辑约束）。
- 惯例：利用用户已有的习惯，降低学习成本；但惯例会随文化与代际变化。

**（6）七阶段行动与两个鸿沟**

```
目标 → 意图 → 动作序列 → 执行 → 感知 → 解释 → 比较
                └── 执行鸿沟 ──┘       └── 评估鸿沟 ──┘
```

- **执行鸿沟**：用户不知道「怎么做」。
- **评估鸿沟**：用户不知道「做成了没有、结果意味着什么」。
- 诊断时逐阶段问：这一步用户需要知道什么？系统提供了吗？

**（7）失误（slip）与错误（mistake）**

- 失误：意图正确，动作执行错（手滑、看错、习惯性操作）。
- 错误：意图或计划本身错（理解错规则、选错目标）。
- 对策不同：失误靠约束、确认、撤销、防呆；错误靠更好的概念模型与信息。

**（8）知识在世界上 vs 知识在头脑中**

- 不要把记忆负担塞进用户脑子。把选项、状态、历史、约束放在界面上。
- 「让用户记住上一步」通常是设计缺陷，不是用户能力问题。

**（9）以人为中心的设计（HCD）**

- 观察 → 构思 → 原型 → 测试 → 迭代。
- 关键不是「问用户想要什么」，而是「观察用户在真实情境中做什么、卡在哪」。

### 概念词典

| 概念 | 含义 | 怎么用 |
|---|---|---|
| 意符 | 提示「可以做什么」的可见线索 | 检查每个可交互元素的可见性 |
| 映射 | 控件与结果的自然对应 | 布局、方向、分组遵循直觉 |
| 反馈 | 动作后的状态告知 | 即时、具体、可行动 |
| 概念模型 | 用户对系统运作的解释 | 用一张图讲清对象/状态/动作 |
| 约束 | 让错误难以发生 | 禁用、校验、限制、确认 |
| 惯例 | 用户已有的习惯 | 遵循主流模式，除非有强理由 |
| 执行鸿沟 | 不知道怎么操作 | 补意符、补示例、补默认值 |
| 评估鸿沟 | 不知道结果如何 | 补状态、补对比、补解释 |
| 失误 | 执行出错 | 防呆、撤销、确认 |
| 错误 | 理解/计划出错 | 改概念模型与信息结构 |

### 诊断问题

1. 用户第一次看到这个界面，知道能做什么吗？靠什么知道？
2. 控件的位置、方向、分组，与结果有自然映射吗？
3. 操作后，用户多久知道发生了什么？反馈是否具体到「下一步」？
4. 用户心里的模型是什么？和系统模型差在哪？
5. 出错时能撤销、恢复、重试吗？
6. 这个步骤是在考验记忆，还是把知识放在了界面上？
7. 这个错误是失误还是误解？设计如何从根上防？
8. 新用户需要读说明书/看培训视频吗？如果需要，是不是模型没设计好？

### 局限与误用

- **把「简洁」当「少显示」**：删掉必要信息会破坏可发现性。简洁是「降低认知负担」，不是「减少像素」。
- **用引导弥补模型缺陷**：新手引导救不了错误的概念模型，只会把问题推迟到第 3 天。
- **把用户错误归因于用户**：说「用户太笨」通常意味着设计者没做用户测试。
- **只做可用性**：诺曼解决「能用」，不解决「想要」「值得」「会上瘾」。

### 与其他镜头的接口

- 俞军判断「值不值得做」，诺曼负责「做出来能不能被理解和使用」；原研哉负责「用起来有没有感觉」；杨堃负责「在真实业务链路里是否成立」。

## 3. 原研哉《设计中的设计》：用户能不能重新「感觉到」

### 一句话

设计不是造物，是让人重新看见已知之物。

### 核心模型

**（1）再设计（RE-DESIGN）**

- 把日常之物拿出来重新设计：卫生纸、火柴、CD 机、茶包……
- 目的不是发明新东西，而是**通过陌生化唤醒感知**：让用户重新注意到「本来就在那里」的细节。
- 对数字产品的启示：不要只做「新功能」，也可以重新设计一个被用麻木的核心动作（注册、搜索、结算、通知）。

**（2）空白（Emptiness / 白）**

- 空白不是空无，是**容纳他者意义的容器**。
- 白是「可能性」：不把话说满，让用户把自己的经验、情绪、解释放进去。
- 在界面里，留白是节奏、是层级、是邀请；不是「没东西可放」。

**（3）信息雕刻**

- 删去冗余，让信息的本质显现。
- 不是装饰，而是组织：通过对比、尺度、秩序、材质，让重要的东西被看见。
- 对数字产品的启示：一屏里最重要的三件事是什么？其余是否应该退后、折叠、延后？

**（4）感官（SENSEWARE / HAPTIC）**

- 触觉、材质、重量、声音、温度，都是信息的一部分。
- 数字产品没有材质，但有：动效的缓动、转场的节奏、文案的语气、加载的等待感、声音与震动。
- 「感官」不是加特效，是让反馈与意义一致。

**（5）沟通设计**

- 设计不是设计师的自我表达，而是建立「物与人」「人与人」之间的关系与理解。
- 好设计让用户感到「这是在跟我说话」，而不是「这是在展示你」。

**（6）克制：「这样就好」**

- 反对过度设计、过度表达、过度功能。
- 克制不是简陋，是**知道什么不该做**。

**（7）以未知为起点**

- 把已知事物重新变成未知（Ex-formation），迫使自己重新观察，而不是套用既有类别。
- 对产品经理的启示：先描述「用户看到的原始现象」，再套用「需求/功能」的类别。

### 概念词典

| 概念 | 含义 | 怎么用 |
|---|---|---|
| 再设计 | 重新设计日常之物以唤醒感知 | 挑一个被用麻木的核心动作重做 |
| 空白 | 容纳他者意义的容器 | 留出解释与投射的空间 |
| 信息雕刻 | 删繁就简，让本质显现 | 用对比与秩序组织信息 |
| 感官 | 材质、触觉、声音、节奏 | 让动效/文案/声音与意义一致 |
| 沟通设计 | 建立关系与理解 | 问「这是在跟谁说话」 |
| 克制 | 知道什么不该做 | 砍掉「显得高级」的装饰 |
| Ex-formation | 把已知重新变成未知 | 先观察现象，再套类别 |

### 诊断问题

1. 这个设计在「说」什么？一句话能说清吗？
2. 删掉 30% 的信息、步骤、装饰后，它还成立吗？删掉的是什么？
3. 用户能否把自己的意义放进去？还是被塞满了 designer 的表达？
4. 有没有一个让人记住的感官瞬间（动效、文案、声音、材质）？
5. 它是在表达设计师，还是在建立与用户的关系？
6. 哪些元素是为了「显得高级」而存在的？
7. 这个界面有没有「呼吸感」？信息密度是否服务于任务？

### 局限与误用

- **把留白当空洞**：留白需要秩序与暗示，否则只是「没做完」。
- **在高风险、高密度 B 端滥用禅意**：巡检、对账、急救场景需要的是清晰与效率，不是意境。
- **用文化符号掩盖功能缺陷**：水墨、留白、侘寂不能替代可用的流程。
- **把「克制」变成「不提供信息」**：克制是删冗余，不是删必要。

### 与其他镜头的接口

- 诺曼保证「看得懂」，原研哉负责「记得住、有感觉、愿意靠近」；俞军保证「值得换」，杨堃保证「在业务里跑得通」。

## 4. 埃亚尔《上瘾》：行为会不会再次发生

### 一句话

习惯 = 被内部情绪触发、以最低摩擦完成、获得可变奖励、并留下投入的循环。

### 核心模型

**（1）Hook 四步**

```
触发（Trigger）→ 行动（Action）→ 可变奖励（Variable Reward）→ 投入（Investment）
        ↑                                                              │
        └──────────────── 外部触发逐渐让位于内部触发 ─────────────────┘
```

**（2）触发**

- 外部触发四类：付费（广告）、赢得（媒体报道/口碑）、关系（邀请/社交）、自有（App 图标/推送/邮件）。
- 内部触发：情绪——无聊、孤独、焦虑、困惑、错过恐惧、求认可。
- 习惯形成的标志：用户不再需要外部提示，情绪一起就打开产品。

**（3）行动：B = MAT**

- Behavior = Motivation × Ability × Trigger。
- 先降低能力门槛，再谈动机；动机不稳定，能力门槛是可控的。
- 能力六要素：时间、金钱、体力、脑力、社会偏差、非常规（是否符合惯例）。

**（4）可变奖励**

- 社交奖励（tribe）：被认可、被回应、归属。
- 猎物奖励（hunt）：资源、信息、机会、稀缺物。
- 自我奖励（self）：掌控、完成、精通、意义。
- 关键不是「随机」，而是**不确定性 + 与核心价值相关**。纯赌博式随机是操纵。

**（5）投入**

- 用户留下：内容、数据、关注关系、声誉、技能、设置。
- 投入的作用：让下一次触发更容易、让产品更有价值、让离开更痛。
- 伦理分界线：投入应当**同时也让用户受益**（更好的推荐、更多的积累），而不是单纯的沉没成本绑架。

**（6）习惯区间**

- 频率 × 感知效用。高频高效用才容易形成习惯；低频产品不要硬做习惯。
- 习惯测试：区分「习惯用户」「普通用户」「流失用户」，看行为 cohort，而不是看平均值。

**（7）操纵矩阵**

|  | 自己会用吗？是 | 自己会用吗？否 |
|---|---|---|
| **能改善用户生活？是** | 促进者（Facilitator） | 兜售者（Peddler） |
| **能改善用户生活？否** | 娱乐者（Entertainer） | 欺骗者（Dealer） |

目标应是「促进者」：既改善用户生活，自己也愿意用。

### 概念词典

| 概念 | 含义 | 怎么用 |
|---|---|---|
| 外部触发 | 外部提示（推送、广告、邀请） | 冷启动期用，后期应减弱 |
| 内部触发 | 情绪引发的自动使用 | 找到产品对应的核心情绪 |
| B=MAT | 行为 = 动机 × 能力 × 触发 | 优先降能力门槛 |
| 可变奖励 | 不确定但相关的奖励 | 与核心价值绑定，不做纯赌博 |
| 投入 | 用户留下的价值 | 让下次更容易，且用户受益 |
| 习惯区间 | 高频 × 高感知效用 | 判断是否值得做习惯设计 |
| 操纵矩阵 | 四类产品伦理定位 | 自检是否在「兜售/欺骗」 |

### 诊断问题

1. 用户不打开产品时，在逃避什么情绪？产品对应哪个内部触发？
2. 第一次使用 30 秒内，用户是否获得核心价值？
3. 触发来自外部还是内部？外部触发是否可逐步撤掉？
4. 行动的最大摩擦是哪一项（时间/金钱/体力/脑力/社会/非常规）？
5. 奖励是否可变？是否与核心价值相关？还是纯随机？
6. 用户投入了什么？投入是否让下次更容易、也更有归属？
7. 产品是否高频到足以形成习惯？如果低频，习惯设计是否在打扰用户？
8. 如果用户完全理解我们的设计意图，还会同意吗？

### 局限与误用

- **低频产品硬做习惯**：保险、年报、体检、B 端审批，硬做签到/推送只会增加反感。
- **用推送替代价值**：把「触达」当「留存」，短期数据好看，长期卸载。
- **可变奖励变成赌博**：老虎机式随机、无限滚动、虚假稀缺，属于操纵。
- **剥削脆弱人群**：未成年人、焦虑/抑郁人群、财务困难人群，应主动设限。
- **忽略「感知效用」**：习惯不是靠频率堆出来的，用户得觉得「值」。

### 与其他镜头的接口

- 俞军判断「这件事值不值得用户反复来」，埃亚尔负责「怎么让反复发生」；诺曼保证每次循环不卡；原研哉让循环里有「值得回味的一瞬」。

## 5. 杨堃《决胜体验设计》：在真实组织与业务链路里能不能落地

### 一句话

B 端体验不是界面美观，而是**业务链路、应用架构、数据架构与角色协作**的综合结果。

### 核心模型

**（1）B 端体验的三个前提**

- 客户 ≠ 用户：付费方、决策方、使用方、IT 维护方的诉求经常冲突。
- 场景 ≠ 功能：先有业务场景与任务，再有功能与页面。
- 体验 ≠ 界面：系统耦合、数据孤岛、信息断层，都会让界面「看起来还行，用起来要命」。

**（2）用户画像**

- 区分**客户画像**（组织/付费方）与**用户画像**（岗位/角色）。
- B 端画像维度：岗位职责、业务目标、KPI、系统熟练度、使用频率、权限范围、异常处理责任。
- 「系统熟练度」是关键维度：新手、熟练者、专家需要不同的信息密度与快捷方式。

**（3）用户调研**

- 五步流程、四类目标（理解业务、发现痛点、验证假设、评估方案）。
- 一对一访谈的十个锦囊：自我介绍、激励动机、场景还原、直击痛点、总结过渡、权威构建、回溯打断、碎片重组、清晰主线、有始有终。
- 其他方法：问卷、焦点小组、可用性测试、观摩实习、数据分析。
- B 端调研的核心不是「问需求」，而是**还原真实工作流与例外**。

**（4）场景地图五步法**

1. 明确画像用户
2. 确定业务目标
3. 推导关键任务
4. 绘制旅程地图
5. 细化业务场景

产物：角色-目标-任务-旅程-场景的链条。它把「用户画像」从一张海报变成可执行的设计输入。

**（5）产品定位与架构**

- 避免「全家桶」：一个系统塞进所有角色与所有功能，最终谁都找不到。
- 子系统划分原则：按业务域、角色、生命周期、变更频率拆分。
- 信息架构与菜单：按任务/对象分类，不按部门/技术分类。
- 企业架构视角：应用架构、数据架构决定了很多「体验问题」的根因。

**（6）设计价值观与原则**

- 「让产品像管家一样贴心」：预判需求、减少操作、兜住异常、不添麻烦。
- 设计原则要能指导取舍，例如：效率优先、异常先行、少即是多、可追溯、可批量。

**（7）页面与组件范式**

- 信息框架：Agent 侧边栏、融合 Agent 的首页、信息流首页、Agent 与全局搜索。
- 工作台四步法：明确画像用户 → 梳理工作事项 → 选择呈现组件 → 设计工作台。
- 表单、列表、详情页的经典范式；ChatBI / Data Agent。
- 关键洞察：B 端大多数页面不是「展示页」，而是「工作任务的处理台」。

**（8）微交互三系统**

- **反馈系统**：三要素、提醒程度（静默/提示/阻断）、场景四问、四个设计要点。
- **促活系统**：上手引导、功能发现、深度学习、行为纠偏；六步法；组件与范式。
- **消息系统**：站内信、Push、第三方 IM、短信/电话、邮件；按紧急度、成本、可达性选渠道。

**（9）AI 时代的人机交互：六脉神剑**

- **剑鞘：任务分诊**。先用二维四象限判断哪些任务交给 AI、哪些保留 GUI、哪些人机协同。
- **第一剑：封装 API**。把系统能力变成 AI 可调用的原子能力，否则 AI 只能「陪聊」。
- **第二剑：CUI 嵌入 GUI**。不要另起一个孤立的聊天框；把对话嵌进现有工作界面（侧边栏、首页、全局搜索、Agent）。
- **第三剑：Chat**。用户主动提问，AI 回答/执行；适合探索、查询、生成、解释。
- **第四剑：Copilot**。AI 在用户工作流中主动建议、补全、预填；适合结构化任务与决策辅助。
- **第五剑：Chat 拆主动/被动**。主动推送（预警、机会）与被动响应（问答）是两种产品。
- **第六剑：Copilot 拆主动/被动**。建议（人确认）与自动执行（人监督）是两种风险等级。
- **人在回环**：AI 建议人确认；人操作 AI 辅助/接管。高风险场景必须保留确认与撤销。

**（10）体验度量**

- 经典：SUS、NPS、CSAT、CES、Google PULSE、HEART、GSM。
- 国内：阿里 1688 五度模型、阿里云 UES、蚂蚁 PTECH。
- B 端选型：任务效率、错误率、一次成功率、培训时长、采纳率、工单量、续费/留存。
- AI 产品：任务完成率、建议采纳率、回退/撤销率、人工接管率、幻觉率、可解释满意度。

### 概念词典

| 概念 | 含义 | 怎么用 |
|---|---|---|
| 客户画像 | 组织/付费方的画像 | 与用户画像分开画 |
| 系统熟练度 | 新手/熟练/专家的差异 | 决定信息密度与快捷方式 |
| 场景地图 | 角色-目标-任务-旅程-场景 | B 端设计的第一张图 |
| 全家桶 | 一个系统塞所有功能 | 用子系统拆分对抗 |
| 工作台 | 角色每天工作的入口 | 四步法设计 |
| 反馈系统 | 状态告知与提醒 | 按提醒程度分级 |
| 促活系统 | 引导、发现、学习、纠偏 | 六步法 |
| 消息系统 | 多渠道触达 | 按紧急度/成本选渠道 |
| 六脉神剑 | AI 交互设计方法 | 先分诊，再选 Chat/Copilot |
| 人在回环 | 人机协同的确认机制 | 高风险必留 |

### 诊断问题

1. 这是谁的场景？在业务链路的哪一环？
2. 客户、用户、决策者、IT 的诉求是否冲突？优先满足谁？
3. 系统边界在哪？数据从哪来、到哪去、谁维护？
4. 异常、权限、并发、离线，谁处理？
5. 这个页面是工作台、表单、列表还是详情？范式选对了吗？
6. 反馈是否在正确的时机、用正确的强度？
7. 新用户如何被促活？老用户如何发现新功能？
8. 用哪个度量模型？口径是什么？和业务指标怎么挂钩？

### 局限与误用

- **把 B 端当 C 端做**：重情感、轻效率；重拉新、轻留存与合规。
- **只画页面不看流程与架构**：界面再美，数据孤岛和权限混乱仍会让体验崩塌。
- **用 NPS 代替 B 端效率指标**：B 端客户少、决策链长，NPS 样本与解释力都有限。
- **功能堆成全家桶**：每个角色都想要自己的入口，最后没有主路径。
- **AI 硬塞进流程**：没有任务分诊、没有 API 封装、没有人在回环，只为「有 AI 而 AI」。

### 与其他镜头的接口

- 杨堃提供「组织与系统」的现实约束，诺曼提供「认知与行动」的微观机制，俞军提供「价值与交易」的取舍标准，原研哉提供「感知与克制」的审美判断，埃亚尔提供「行为持续」的循环设计。

## 6. 五镜如何协同：按任务类型编排

| 任务 | 第一步 | 第二步 | 第三步 | 产出 |
|---|---|---|---|---|
| 0→1 新产品 | 俞军：价值与交易 | 诺曼：概念模型与主流程 | 原研哉：体验原则 | 设计简报 + 原型 |
| 功能迭代 | 诺曼：七阶段诊断 | 俞军：价值增量 | 杨堃：异常与权限 | 任务流 + 验收 |
| 体验优化 | 诺曼：卡点定位 | 杨堃：场景与度量 | 原研哉：层级与留白 | 修复清单 |
| 留存/习惯 | 埃亚尔：Hook | 俞军：价值是否成立 | 伦理审查 | Hook 工作表 |
| B 端系统 | 杨堃：场景地图 | 诺曼：工作台与表单 | 俞军：角色间交易 | IA + 页面范式 |
| AI 功能 | 杨堃：任务分诊 | 诺曼：人机分工 | 埃亚尔：使用频率 | 交互模式 + 度量 |
| 品牌/高端体验 | 原研哉：感知与克制 | 诺曼：可发现性 | 俞军：支付意愿 | 体验原则 + 关键界面 |

**协同的三个禁忌**

1. 不要用埃亚尔的「频率」逻辑去要求低频 B 端产品。
2. 不要用原研哉的「留白」去削减高风险场景的必要信息。
3. 不要用俞军的公式去替代真实的用户观察——公式是整理器，不是探测器。
