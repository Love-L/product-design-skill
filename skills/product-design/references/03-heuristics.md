# 判断规则、反模式与伦理边界

> 这份文件回答三个问题：**该用哪招**、**什么时候会用错**、**什么不能做**。

---

## 一、镜头选择决策树

```
用户提出设计任务
│
├─ 是「评审」吗？
│   └─ 是 → 用 assets/review-checklist.md，五镜全覆盖
│
├─ 涉及 AI 能力 / Copilot / Agent / 对话式交互吗？
│   └─ 是 → 先做任务分诊（六脉神剑·剑鞘）
│            → 再选 Chat / Copilot / 嵌入 GUI
│            → 必查人在回环与度量（references/04）
│
├─ 是多角色、权限、流程、组织系统吗？
│   └─ 是 → 杨堃：场景地图 → 架构/IA → 页面范式 → 度量
│            → 诺曼补工作台与表单的认知走查
│
├─ 目标主要是「留存 / 习惯 / 复访」吗？
│   └─ 是 → 先判断：高频？价值可累积？用户主动？
│            ├─ 否 → 放弃 Hook，回到价值与场景
│            └─ 是 → 埃亚尔四步 + 伦理四问 + 实验
│
├─ 是已上线产品的体验问题吗？
│   └─ 是 → 诺曼七阶段诊断 → 杨堃场景/度量 → 原研哉层级
│
└─ 0→1 的 C 端产品
    └─ 俞军（价值/交易）→ 诺曼（模型/流程）→ 原研哉（感知）→ 埃亚尔（复访）
```

**一条兜底规则**：如果你不确定用哪个镜头，先用**诺曼的七阶段**走一遍主任务。它几乎总能暴露一个具体问题，而具体问题会告诉你该叫哪个镜头。

## 二、25 条 if-then 规则

### 关于问题定义

1. **如果用户说「加个功能」**，先问「现在用户怎么绕过这个问题」。绕过方式就是旧体验，也是你真正的竞品。
2. **如果老板提出一个具体功能**，先还原他背后的业务目标，再判断这个功能是不是最优解；不要直接执行，也不要直接反驳。
3. **如果方案里出现「教育用户」**，先检查概念模型。教育是成本，不是设计。
4. **如果两个角色的诉求冲突**，按「谁承担后果」排序，而不是按职级或声音大小。

### 关于价值与取舍

5. **如果新体验只省 10% 时间，替换成本却要 1 小时**，先做迁移工具与默认值，不要做推广。
6. **如果方案越做越大**，回到非目标，砍到只剩一个主场景；剩下的写进「以后」。
7. **如果竞品加了一个功能**，先问「它的用户结构、使用场景、商业模式和我们一样吗」；不一样，就不构成理由。
8. **如果团队争论「要不要做」**，把它变成一个可验证的假设与一个便宜实验，而不是继续开会。
9. **如果一件事可逆**，快速做、快速改；**如果不可逆**（定价、数据迁移、品牌承诺），慢做、多验证。

### 关于认知与交互

10. **如果用户犯错率高**，先改约束、默认值、可撤销，不要先加提示文案。
11. **如果界面需要说明文字才能理解**，把说明变成结构（分组、顺序、示例），而不是把字放大。
12. **如果新用户第一分钟没有获得价值**，先做「首次价值」路径，不要做新手引导。
13. **如果一屏放不下**，先问「用户此刻的任务是什么」，而不是压缩字号或加折叠。
14. **如果用户需要记住上一步**，把上一步的状态放在界面上。
15. **如果操作不可撤销**，加确认；**如果确认太频繁**，改成可撤销。

### 关于行为与习惯

16. **如果产品低频**，不要做签到、连续天数、勋章；把力气花在「每次都用得值」。
17. **如果留存低但体验不差**，先查「价值是否可累积」与「内部触发」，不要加推送。
18. **如果数据涨了但投诉也涨**，检查是不是靠打扰、诱导、隐藏退出换来的。
19. **如果用户要求「上瘾」**，先做伦理四问，再判断频率与价值；不满足就明确拒绝。
20. **如果奖励是纯随机**，改成「不确定但相关」；前者是赌博，后者是惊喜。

### 关于 B 端与组织

21. **如果 B 端客户要求「全家桶」**，先拆角色与场景，再划子系统边界；一个入口服务所有人，等于谁都找不到。
22. **如果 B 端需求来自老板而非用户**，区分「客户价值」与「用户价值」；两者冲突时，先找双赢方案，再谈取舍。
23. **如果异常流程没人写**，先写异常，再写正常；B 端的体验差距主要在异常。
24. **如果 B 端指标只有 NPS**，补任务效率、错误率、一次成功率、培训时长、工单量。

### 关于 AI

25. **如果 AI 功能只是一个聊天框**，先做任务分诊与 API 封装；没有原子能力，对话只是陪聊。

> **红线（不是 if-then，不可协商）**：如果 AI 建议会改变数据、金钱、权限或对外承诺，必须人在回环 + 可撤销 + 可追溯。

## 三、反模式清单

| # | 反模式 | 表现 | 后果 | 替代做法 |
|---|---|---|---|---|
| 1 | 方案伪装成问题 | 「做一个 XX 功能」当问题陈述 | 解决错的问题 | 用「角色-场景-障碍-替代」句式重写 |
| 2 | 用户标签化 | 「25–35 岁女性」当用户画像 | 设计无的放矢 | 拆角色 × 场景 × 任务 |
| 3 | 忽略旧体验 | 只对比竞品，不算用户现状 | 低估替换成本 | 访谈「你现在怎么做」 |
| 4 | 功能堆砌 | 每个角色都要入口 | 主路径消失 | 非目标 + 子系统拆分 |
| 5 | 用引导补模型 | 新手引导 8 步 | 第 3 天仍不会用 | 重做概念模型 |
| 6 | 用推送补价值 | 日推 3 条 | 短期留存、长期卸载 | 先做首次价值与内部触发 |
| 7 | 赌博式奖励 | 随机抽奖、无限滚动 | 成瘾、信任崩塌 | 与核心价值相关的可变奖励 |
| 8 | 沉没成本绑架 | 投入越多越难走，但用户没受益 | 用户反感、口碑受损 | 投入同时提升用户价值 |
| 9 | 把 B 端当 C 端 | 重情感、轻效率 | 专业用户流失 | 密度、批量、键盘流、异常可见 |
| 10 | 只画页面不看架构 | 界面精美，数据孤岛 | 体验在系统层崩塌 | 场景地图 + 应用/数据架构 |
| 11 | 异常一句带过 | 「提示错误」 | 真实工作流走不通 | 异常流 ≥ 正常流 1/3 |
| 12 | 审美争论 | 评审变成「我觉得不好看」 | 无法收敛 | 回到问题、任务、原则 |
| 13 | 指标虚荣 | 只看 PV/UV/注册数 | 看不到真实价值 | 任务成功 + 留存/效率 |
| 14 | 事后改口径 | 没达标就换指标 | 组织失去判断力 | 预注册指标与放弃条件 |
| 15 | 可用性测试作秀 | 只找友好用户、只测顺利任务 | 假阳性 | 挑剔用户 + 真实任务 + 异常 |
| 16 | 过度留白 | 为了「高级」删必要信息 | 可发现性下降 | 留白服务于层级，不牺牲信息 |
| 17 | 术语治理 | 用「赋能/闭环」代替机制 | 团队无法执行 | 说清谁做什么、怎么发生 |
| 18 | AI 硬塞 | 为「有 AI」而加聊天框 | 用户不用、成本上升 | 任务分诊 + API + 人在回环 |
| 19 | 一次性交付 | 上线即结束 | 无法迭代 | 灰度、埋点、复盘 |
| 20 | 伦理后置 | 先增长再补合规 | 返工、处罚、信任损失 | 设计时做伦理四问 |

## 四、伦理边界：四问与红线

### 四问（每个涉及行为设计的功能都过一遍）

1. **透明性**：如果用户完全理解我们的设计意图，还会同意吗？
2. **受益性**：用户长期是变得更好，还是更依赖、更焦虑、更穷？
3. **可退出性**：取消、退款、关闭、注销，是否和开通一样容易？
4. **脆弱性**：是否针对未成年人、成瘾人群、财务困难人群、情绪脆弱人群？

### 红线（不做）

- 虚假稀缺/倒计时造假
- 虚构社会证明（假评论、假在线人数）
- 隐藏取消入口、退出障碍
- 强制连续（断签惩罚、焦虑驱动）
- 赌博式随机奖励
- 恐惧/羞耻胁迫
- 暗黑默认（默认勾选、默认续费）
- 针对未成年人的成瘾性无限滚动

### 处理方式

- 用户要求做红线功能时：说明具体机制、长期代价与替代方案；不配合实现。
- 边界模糊时：给出「可做版本」与「不可做版本」的对比，让用户选择可做版本。
- 高风险领域（医疗、金融、未成年人、公共安全）：优先合规与安全，其次体验与增长。

## 五、评审评分表

> 完整清单见 `assets/review-checklist.md`；这里是评分与结论规则。

### 六个维度（每项 0–3 分）

| 维度 | 3 分 | 1 分 | 0 分 |
|---|---|---|---|
| 问题定义 | 清晰、有证据、非目标明确 | 模糊或含方案 | 缺失 |
| 用户与场景 | 角色×场景×任务完整 | 只有人群标签 | 没有用户 |
| 价值与交易 | 三项有证据、反证条件清晰 | 只有定性判断 | 没有价值论证 |
| 概念模型与流程 | 一张图讲清、异常完整 | 有流程但模型不清 | 只有页面清单 |
| 行为与反馈 | 每步有反馈、伦理通过 | 有反馈但不完整 | 无反馈设计 |
| 验证与度量 | 假设-实验-指标闭环 | 有指标无实验 | 无验证 |

### 结论规则

- **通过**：总分 ≥ 15，且无 0 分项。
- **有条件通过**：总分 10–14，或存在 1 个 0 分项但有明确补救计划。
- **不通过**：总分 < 10，或「问题定义」「价值」任一为 0。

### 分级

| 级别 | 定义 | 处理 |
|---|---|---|
| CRITICAL | 方案不成立/有伦理/合规风险 | 必须先解决 |
| HIGH | 会导致返工或明显失败 | 本轮解决 |
| MEDIUM | 影响体验或效率 | 排期解决 |
| LOW | 优化项 | 记录 |

## 六、指标库

### C 端

| 指标 | 定义 | 口径注意 |
|---|---|---|
| 激活率 | 完成首次价值动作 / 新用户 | 「价值动作」要定义 |
| 次日/7 日留存 | 次日/7 日回访 / 当日新增 | 区分自然回访与推送召回 |
| 任务完成率 | 完成主任务 / 开始主任务 | 要定义「完成」 |
| 频次 | 人均周使用次数 | 分新老用户 |
| NPS | 推荐意愿 | 样本偏差、行业基准 |

### B 端

| 指标 | 定义 | 口径注意 |
|---|---|---|
| 任务效率 | 单任务时长/步骤数 | 按角色、按场景拆分 |
| 一次成功率 | 首次即成功 / 总尝试 | 最能反映体验 |
| 错误率 | 操作错误 / 总操作 | 区分失误与误解 |
| 培训时长 | 达到熟练所需时间 | 新员工上岗 |
| 采纳率 | 使用新功能的人 / 目标人 | 防止「上线即完成」 |
| 工单量 | 单位用户工单数 | 分类型 |
| 续费/留存 | 客户续费、席位留存 | 与 NPS 交叉看 |

### AI 产品

| 指标 | 定义 | 口径注意 |
|---|---|---|
| 任务完成率 | AI 辅助下完成任务 / 总任务 | 与纯人工对比 |
| 建议采纳率 | 采纳建议 / 展示建议 | 区分主动/被动 |
| 回退/撤销率 | 撤销 AI 操作 / AI 操作 | 高则说明信任或准确率问题 |
| 人工接管率 | 转人工 / 总会话 | 可作为质量信号 |
| 幻觉率 | 事实错误 / 抽样回答 | 需人工标注 |
| 可解释满意度 | 对解释的评分 | 与信任相关 |

### 指标选择三原则

1. **一个北极星**：任务成功或价值实现，不是 DAU。
2. **两层拆解**：行为层（可干预）+ 结果层（可验证）。
3. **预注册**：口径、窗口、放弃条件，在实验前写死。

## 七、取舍矩阵

当多个方案都「有道理」时，用四维打分（1–5）：

| 方案 | 用户价值 | 交付成本（越低越高分） | 风险（越低越高分） | 可逆性 | 总分 |
|---|---|---|---|---|---|
| A | | | | | |
| B | | | | | |

规则：

- 可逆性低 + 风险高 → 先做小实验，不要直接全量。
- 用户价值接近时，选交付成本低、可逆性高的。
- 不要用总分掩盖「某一维为 1」的硬伤；硬伤单独讨论。
